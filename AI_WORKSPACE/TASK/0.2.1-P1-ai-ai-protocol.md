# 0.2.1-P1：正式 AI↔AI 协议

状态：开发中

## 目标

把当前临时的「Decision AI 回复 → 自动调用 Worker AI → 再调用 Decision AI」改成显式协议驱动的 AI↔AI 交接。

## 本轮范围

- 定义最小协议版本 V0.1
- WORK_REQUEST
- WORK_RESULT
- DECISION_REQUEST
- task_id 仅作为协议关联标识，不建设完整 Task 平台
- Decision AI 仅在产生 WORK_REQUEST 时触发 Worker
- Worker 仅在产生 DECISION_REQUEST 时触发 Decision
- 普通模型文字不再自动触发另一 AI
- 保留现有 BridgeFS 指令执行链

## 暂不做

- Tool Calling Runtime
- echo_test
- GitHub Tool
- Actions / Verify
- Task / Execution / Event 持久化
- Android 重启恢复
- Remote Runtime

## 当前实现

- 新增 BridgeCollaborationProtocol.kt
- MainActivity 的 AI 交接改为协议识别后再触发
- 补齐 buildAiSystemPrompt()
- 协议消息使用 JSON envelope 传递给另一 AI

## 验收

1. 工程可以正常构建。
2. 普通 AI 回复不会自动触发另一 AI。
3. Decision AI 输出 WORK_REQUEST 时才触发 Worker。
4. Worker 输出 DECISION_REQUEST 时才触发 Decision。
5. WORK_RESULT 不再自动形成无限 AI→AI 循环。
6. 真实 Provider + Model 的协议遵循情况在后续 E2E 测试中验证。
