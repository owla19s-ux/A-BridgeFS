# 项目主页 UI 设计（V0.2.1）

状态：**已确认 / 未实现**

> 本文记录 2026-10-04 确认的新版项目主页方案。它是 UI 设计基准，不代表当前 APK 已实现。

## 1. 页面定位

主页面首先是**项目区**，不是旧版“Decision AI / Worker AI 工作区”。

核心关系：

**项目 → 任务 → 对话 → API**

AI 是能力，不作为页面中的固定角色分类。

## 2. 项目总览

默认进入项目页时：
- 项目列表是主入口。
- 所有项目默认收起。
- 每个项目是一个可展开/收起的项目滑块。
- 项目列表用于总览项目状态。
- 项目状态使用四级颜色：🟢 绿：正常；🟡 黄：提示/需要关注；🟠 橙：警告；🔴 红：严重/需要人工处理。
- 颜色应具有稳定、可解释的状态规则，不应由 AI 随意改变。

## 3. 项目展开

点击某个项目后：
- 当前项目进入项目工作面。
- 其他项目暂时不可见。
- 再次收起当前项目后，恢复项目总览。
- 这不是普通的“在项目列表中展开一小块”，而是当前项目占据主内容区域。

项目工作面包含：
1. 项目信息
2. 项目配置入口
3. 待处理
4. 对话区
5. 协助
6. 输入区

## 4. 项目信息与项目配置

项目基本信息至少包括：
- 项目地址
- 当前 API

**项目设置默认不展开。**

项目设置是一个独立入口，点击后才展开/进入管理区域。

项目设置可以管理：项目名称、项目地址、API 绑定、API 的增加/替换/减少或解绑、删除项目、其他项目级配置。

API 边界：
- 全局 API 库：API 本身的配置与生命周期。
- 项目 API 绑定：项目当前使用哪些 API。
- 删除项目不应误删 API 本身。
- 一个项目不应被设计成只能永久绑定一个 API；至少需要为默认 API、可用 API 以及运行时协助 API 留出空间。

## 5. 待处理任务

项目设置下方是**待处理**滑块，任务优先于历史对话。

任务是项目中的工作对象，不是新的 AI 模式。

示例：
- ☐ UI 输入框问题
- ☐ 构建问题
- ☐ 签名冲突

任务使用**勾选框**。

勾选任务后，该任务自动以 @任务 形式加入当前输入框。可以同时勾选多个任务，例如：@任务A @任务B。

然后用户可以自由询问、讨论、分析、解决。UI 不预设“决策/施工”模式。

## 6. 对话区

项目内的对话区保存**历史对话记录**。

例如：主开发、UI 审查、构建检查、GitHub 检查。

对话区本身可以独立收起/展开。点击具体历史对话后，进入对应对话。

任务与历史对话是不同对象：
- 任务：当前需要处理的事项。
- 对话：项目历史工作记录。

## 7. 协助 API

项目内保留“协助”入口。

协助用于当前任务或当前对话需要其他 API 参与时使用。

不重新建立 Decision AI / Worker AI 之类的固定角色。

关系可以是：**当前 API → 当前任务/对话 → 协助 API**。

协助 API 属于具体操作关系，不应被固化成新的 AI 身份。

## 8. 输入区

只有项目展开后，项目输入区才出现。

输入区支持后续扩展：普通输入、+、@、扩大输入区域、语音发送。

任务勾选产生的 @任务 应进入这里。

## 9. 底部页面切换区

页面底部保留 App 自己的页面切换区。

页面切换区右侧增加一个**上下箭头按钮**：
- ↑：当前处于收起/普通显示状态时，用于增加项目工作面的屏幕显示空间。
- ↓：当前处于展开显示状态时，用于恢复较小显示区域。

这个上下按钮**只控制屏幕显示空间**。

它不得自动展开项目配置、自动收起项目配置、改变待处理滑块状态、改变对话区状态或改变项目本身状态。

项目配置仍然只由项目配置入口独立控制。

## 10. Android 系统导航区域

App 页面切换区下面必须保留 Android 系统导航栏/手势安全区域。

底部结构：**内容区 → App 页面切换区 → Android System Bar**。

要求：
- 页面切换区不能覆盖 System Bar。
- 输入区不能覆盖页面切换区。
- 全面屏手势环境下仍应有明确、可操作的页面展开/收起入口。
- 键盘弹出时正确处理 Window Insets。

## 11. 推荐交互状态

### 项目总览
项目列表 → 选择项目

### 项目工作面
项目 → 项目信息 / 配置 / 待处理 / 对话 / 协助 / 输入

### 任务处理
勾选任务 → @任务进入输入框 → 询问/讨论/解决 → 必要时协助 API

### 返回项目总览
项目收起后恢复项目列表。底部显示控制不等同于项目状态控制。

## 12. 明确废弃的旧 UI 思路

本方案不再采用：
- Decision AI / Worker AI 两种固定 UI 分类
- 通过 AI 角色区分“决策”和“施工”
- 将项目、工作区、AI 角色、对话混成同一层级
- 为任务单独制造新的 AI 工作模式

## 13. 设计原则

- 项目是第一层实体。
- 任务是可引用的工作对象。
- 对话是历史工作记录。
- API 是可调用能力。
- 项目配置独立于屏幕显示展开状态。
- 底部上下按钮只控制显示空间。
- 移动端优先，保持主页面低负担。
- UI 必须对应真实业务功能，不能只做视觉上的“假入口”。
