# APS 0.1.2 后续需求清单

状态：后续版本候选范围；不属于 APS 0.1.1 的默认阻塞项

## 1. 版本定位

0.1.2 用于承接 0.1.1 交付过程中发现、但不影响当前版本核心安全性、构建或已确认需求的后续能力。

此清单是需求登记，不表示已承诺全部实现。进入 0.1.2 施工前，应根据 0.1.1 实际使用和验证证据重新排序。

## 2. 模块管理

后续按真实需求设计统一模块管理能力，候选功能包括：

- 模块添加 / 注册；
- 配置、修改与连接验证；
- 部署 / 安装、启动、停止；
- 更新、版本兼容性检查；
- 删除 / 卸载；
- 当前状态、最近错误与运行记录；
- 依赖关系、权限申请、升级失败回滚；
- 来源、版本、许可证和完整性信息的可追溯记录。

这些功能需要分别定义状态与失败语义。不能把“添加配置”“部署文件”“启动运行”当成同一个动作，也不能默认所有模块都支持每一种生命周期操作。

## 3. 第三方模块与浏览器能力

- 继续验证 Microsoft Playwright MCP 等候选模块的 Android / ARM64 运行可行性。
- 先确认运行环境、通信方式、进程隔离、超时 / 取消和资源释放，再决定是否纳入正式连接目录。
- 浏览器操作按只读、普通交互、敏感操作分级授权；提交、删除、支付等敏感操作需要独立确认。
- 本地会话 / 浏览器配置文件默认隔离；只有用户明确启用时才考虑持久化登录态。
- 远程控制端不得默认暴露给局域网；认证、来源校验和端口暴露策略需单独验证。
- 不将 Node.js / Playwright 的桌面运行要求误认为 Android 兼容证据。

## 4. 连接层增强

- 按真实需求扩展 Connection / Connector 的能力声明和公共生命周期契约。
- 完善 AI/API 模型发现、模型配置、服务差异、错误语义与连接诊断。
- 细化 GitHub 读取、文件修改、工作流触发等权限，避免使用过粗的统一写入开关。
- 完善 Local/File 的文件类型、读写能力、权限失效和冲突处理。
- 评估 API 端点校验、传输安全、凭证存储与日志脱敏的进一步加固。

## 5. 架构与协作能力候选项

- 多 AI 协作施工协议与交接回执；
- Context 工作状态共享、并行 Task 和资源冲突控制；
- Receipt / Evidence 的正式协议；
- 更复杂的 Dispatcher 协作状态与恢复；
- 如有真实收益，再评估 Gradle 多模块工程化。

## 6. 进入施工的条件

每项候选需求进入实施前，至少明确：

1. 对 0.1.1 的实际影响或新增使用场景；
2. 用户可见行为和数据边界；
3. 依赖、权限和安全影响；
4. 可执行的验收标准；
5. 与当前主链的兼容性和回退方式。

在此之前，候选需求只登记、不要求暂停 0.1.1，也不因其存在而提前建设通用平台。
