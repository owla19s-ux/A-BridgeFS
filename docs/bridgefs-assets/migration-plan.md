# BridgeFS+ 迁移计划

## 当前目标

以旧 BridgeFS 已验证能力为基础，快速建立 A-BridgeFS 的第一版核心链路：

```text
API / 本地聊天
        ↓
BridgeFS 指令识别
        ↓
现有本地执行能力
        ↓
回执
```

## 第一阶段

直接验证：

1. API 输入能够进入 BridgeFS
2. 本地聊天能够进入 BridgeFS
3. 两种输入复用统一指令识别与执行能力
4. 执行结果形成回执

## 第二阶段

在第一阶段稳定后，再加入：

- API 配置管理
- 角色系统
- 多 API 协作
- 回执检查/调度唤醒

## 架构原则

- API 与角色解耦
- AI 不直接拥有本地执行权限
- BridgeFS 负责本地执行与回执
- 项目/任务状态最终应独立于具体模型
- 不为了新架构而重复实现已经验证的 BridgeFS 能力

## 当前明确不做

- 不先实现完整多 Agent 系统
- 不先实现复杂长期记忆
- 不先重写指令识别核心
- 不把旧 BridgeFS UI 原样迁移为最终产品 UI
