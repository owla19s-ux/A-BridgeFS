# A-BridgeFS 需求板

更新时间：2026-09-30

> 本文件是当前需求板，不等同于最终产品路线图。需求状态以真实验证结果推进。

## P0 — 当前实验

### R-001 Decision AI → Worker 连续施工

**状态：开发中 / 待验证**

目标：

一次明确的施工授权，应允许 Worker 在规定边界内连续完成当前阶段，而不是每做一个小动作就要求用户输入“继续”。

验收方向：
- 明确当前施工目标与边界。
- Worker 能连续处理普通实现问题。
- 正常 Commit / Verify / 重试不要求用户逐次输入“继续”。
- 真正需要决策时才暂停。
- 阶段完成后再汇报。

### R-002 小问题自主处理

**状态：开发中 / 待验证**

Worker 应能够自行处理明确、低风险、属于当前任务范围的小问题。

例如：
- 编译错误
- 测试辅助代码错误
- 明确的实现遗漏
- 格式或命名问题

不得自行改变：
- 已确认的架构原则
- 用户明确的产品行为
- 任务范围
- 权限边界

### R-003 Decision AI 与 Worker 自动对接

**状态：已设计未实现**

目标：

Worker 遇到真正的决策级问题时，可以把结构化问题交给 Decision AI；Decision AI 返回决策后，Worker 自动恢复施工。

基本链路：

Worker
→ 决策请求
→ Decision AI
→ 决策结果
→ Worker
→ 继续施工

第一版不做多 Decision AI，不做多 Worker 调度。

### R-004 Verify 工序确认

**状态：开发中**

目标：

Commit 后确认对应 Verify 是否真正触发，并读取真实结果。

基本事实链：

Commit SHA
→ Check Runs / Workflow Runs
→ Workflow Job
→ 实际结果

不能用“配置上应该触发”代替实际确认。

### R-005 A-BridgeFS 协作回执

**状态：开发中**

目标：

用户能够看到项目当前处于：
- WAITING
- RUNNING
- SUCCESS
- FAILURE
- BLOCKED

并看到必要的下一步，而不是 CI 内部流水账。

## P1 — 运行一段时间后再决定

### R-006 协作日志

**状态：已设计未实现**

记录：
- 时间
- 项目
- 操作者
- 指令
- Worker 回执
- 状态
- Commit / Verify 关联

协作日志必须与运行日志、崩溃日志分离。

### R-007 权限边界

**状态：候选**

逐步验证：
- 读取仓库
- 修改代码
- Commit
- 测试
- PR
- 合并
- Secrets / 部署 / 仓库设置

原则：最小必要权限。

### R-008 等待外部工序

**状态：候选**

需要验证 Worker 是否能够理解：
- 为什么等待
- 等什么
- 哪个工序负责结果
- 结果对应哪个 Commit
- 什么时候继续
- 继续回到哪个施工节点

## P2 — 暂不施工

- 多 Worker
- 复杂任务调度
- 完整项目管理
- 自动任务队列
- 完整 Agent 平台
- 多层 Decision AI
- 大规模权限系统
- 复杂知识库 / 长期记忆

## 需求状态定义

- **待讨论**：尚未形成明确需求
- **候选**：有价值，但尚未决定施工
- **已确认**：方向已经确定
- **开发中**：正在施工
- **已实现**：代码已完成，但未完成最终验证
- **已验证**：真实测试确认
- **阻塞**：存在明确阻塞因素
- **废弃**：不再作为当前方向
