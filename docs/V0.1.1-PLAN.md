# A-BridgeFS v0.1.1 第一版计划

> 状态：第一版计划
>
> 目标：先验证 A-BridgeFS 的最小 AI → 授权 → BridgeFS → 真实执行 → 结果返回闭环。
>
> 本文是 v0.1.1 的范围基线。未来协作空间、多 AI 角色、自动调度等属于后续方向，不自动纳入本版本。

## 1. 版本定位

A-BridgeFS v0.1.1 不是完整的 AI 协作平台，也不是新的聊天软件。

第一版首先解决一个核心问题：

**让 AI 能够在用户明确授权的前提下，通过 A-BridgeFS 调用真实执行能力，并获得可追踪的执行结果。**

最小闭环：

```
人
 ↓
A-BridgeFS
 ↓
AI / API
 ↓
用户授权
 ↓
BridgeFS
 ↓
本地真实执行
 ↓
执行结果
 ↓
A-BridgeFS
```

## 2. 项目关系

```
A-BridgeFS
│
├─ AI / API 层
│
├─ 授权与指令层
│
├─ 协作基础层
│
└─ 执行连接层
   └─ BridgeFS
      └─ Android / 本地文件执行
```

BridgeFS 是当前第一种真实执行端，不等于整个 A-BridgeFS。

以后可以继续连接 Git、GitHub、浏览器、云服务和其他工具。

## 3. v0.1.1 必须完成

### 3.1 基础项目骨架

- [ ] A-BridgeFS 基础 Android 工程可稳定构建
- [ ] 项目基本页面可运行
- [ ] 基础配置与数据结构确定
- [ ] 保持独立的 applicationId / namespace
- [ ] GitHub Actions 自动构建可用
- [ ] latest Release 固定 APK 下载链可用

### 3.2 AI / API

第一版支持接入外部 AI API。

基本链路：

```
用户输入
 ↓
A-BridgeFS
 ↓
API Provider
 ↓
Model
 ↓
AI 返回
```

架构不要把角色和具体厂商绑定。

采用：

```
Role
 ↓
Provider
 ↓
Model
 ↓
API
```

第一版可以只有一个 AI，但不能从架构上锁死为某一家模型。

### 3.3 指令 / 授权

AI 产生需要真实执行的操作后，不直接获得无限本地权限。

至少区分：

- 操作类型
- 目标目录 / 文件
- 是否需要用户确认
- 是否允许执行

基本模型：

```
AI 请求
 ↓
A-BridgeFS 授权判断
 ↓
允许 / 确认后允许 / 拒绝
 ↓
BridgeFS 执行
```

Android 系统权限和 AI 的操作权限是两个层次。

### 3.4 BridgeFS 连接

第一版优先复用现有 BridgeFS 能力，不重新实现一套 Android 本地文件执行系统。

需要验证：

```
A-BridgeFS
 ↓
执行请求
 ↓
BridgeFS
 ↓
本地文件
 ↓
BridgeFS 返回结果
 ↓
A-BridgeFS
```

执行结果至少能够表达：

- 成功 / 失败
- 实际操作
- 目标
- 返回信息
- 时间

### 3.5 最小记录

第一版需要能够保留最基本的执行记录。

例如：

```
任务
├─ 请求
├─ 授权结果
├─ 执行操作
├─ 执行结果
└─ 时间
```

这里的记录是为了验证“项目状态不依赖某个 AI”。

但第一版暂时不建设复杂知识图谱或复杂记忆系统。

## 4. 第一版验证案例

使用 BridgeFS 作为真实执行端。

测试案例：

```
人：
让 AI 在指定项目目录创建一个测试文件

↓

A-BridgeFS：
接收 AI 操作请求

↓

授权：
用户确认允许

↓

BridgeFS：
执行文件写入

↓

BridgeFS：
返回执行结果

↓

A-BridgeFS：
记录结果并展示

↓

人：
检查真实文件
```

第二个测试案例：

```
AI 请求读取指定项目目录
 ↓
A-BridgeFS 判断权限
 ↓
BridgeFS 执行读取
 ↓
返回目录 / 文件结果
 ↓
A-BridgeFS 展示
```

如果以上闭环稳定，v0.1.1 的核心目标基本成立。

## 7. 成功标准

v0.1.1 不以功能数量判断完成度。

核心成功标准只有：

### 标准 A：真实执行

AI 请求可以经过 A-BridgeFS 和授权后，真正让 BridgeFS 执行本地操作。

### 标准 B：真实结果

执行结果能够返回 A-BridgeFS，而不是只在聊天中声称“已经完成”。

### 标准 C：可追踪

至少能够知道：

```
谁请求
→ 请求什么
→ 是否授权
→ 实际执行什么
→ 是否成功
→ 返回什么
```

### 标准 D：项目独立于 AI

更换 AI / Provider 后，已有的基础记录和执行结果不会随模型消失。

### 标准 E：构建可复现

源码 Commit 与 APK 构建关系明确。

对外下载统一使用：

```
https://github.com/owla19s-ux/A-BridgeFS/releases/latest/download/A-BridgeFS.apk
```

## 8. 版本边界

v0.1.1 的核心不是：

> “做出一个完整的 AI 协作空间。”

而是：

> **证明 A-BridgeFS 可以把 AI 的能力与用户授权、真实执行环境连接起来，并让真实结果重新回到项目中。**

完成这个最小闭环之后，再继续向多 AI 协作空间扩展。
