# A-BridgeFS 项目需求功能书

更新时间：2026-09-30

> 统一记录需求、功能、UI、协作机制与值得保留的想法。
> 记录 ≠ 确认。状态随讨论、施工和真实验证推进。

## 一、当前项目方向

A-BridgeFS 当前定位为 AI 协作移动端控制入口。

当前第一实验：

人
→ A-BridgeFS
→ Decision AI / Worker
→ GitHub 项目
→ Commit / Verify
→ 回执
→ 人

当前优先真实运行，不急于平台化。

---

## 二、需求与功能

### R-001 Decision AI → Worker 连续施工

**状态：开发中 / 待验证**

一次明确的施工授权，应允许 Worker 在规定边界内连续完成当前阶段，而不是每个小动作都要求用户输入“继续”。

验收方向：
- 明确当前施工目标与边界。
- Worker 能连续处理普通实现问题。
- 正常 Commit / Verify / 重试不要求用户逐次输入“继续”。
- 真正需要决策时才暂停。
- 阶段完成后再汇报。

### R-002 小问题自主处理

**状态：开发中 / 待验证**

Worker 可自行处理明确、低风险、属于当前任务范围的小问题。

不得自行改变：
- 已确认的架构原则
- 用户明确的产品行为
- 任务范围
- 权限边界

### R-003 Decision AI 与 Worker 自动对接

**状态：已设计未实现**

Worker 遇到真正的决策级问题时，交给 Decision AI；获得决策后自动恢复施工。

Worker
→ 决策请求
→ Decision AI
→ 决策结果
→ Worker
→ 继续施工

第一版不做多 Decision AI、多 Worker 调度。

### R-004 Verify 工序确认

**状态：开发中**

Commit 后必须确认对应 Verify 是否真正触发，并读取真实结果。

事实链：

Commit SHA
→ Check Runs / Workflow Runs
→ Workflow Job
→ 实际结果

### R-005 A-BridgeFS 协作回执

**状态：开发中**

用户看到项目当前状态：
- WAITING
- RUNNING
- SUCCESS
- FAILURE
- BLOCKED

只显示必要信息，不展示 CI 内部流水账。

### R-006 协作日志

**状态：已设计未实现**

记录：
- 时间
- 项目
- 操作者
- 指令
- Worker 回执
- 状态
- Commit / Verify 关联

与运行日志、崩溃日志分离。

### R-007 权限边界

**状态：候选**

逐步验证：
- 读取仓库
- 修改代码
- Commit
- 测试
- PR
- 合并
- Secrets / 部署 / 仓库设置

原则：最小必要权限。

### R-008 等待外部工序

**状态：候选**

验证 Worker 是否能够理解等待原因、等待对象、负责工序、对应 Commit、继续条件以及恢复位置。

### R-010 Worker 汇报粒度

**状态：候选**

观察：A-177 当前施工过程中，即使只是测试语义分析、排除一个假设、继续只读检查，也可能形成一小段一小段的阶段性汇报。

期望方向：

Worker 在获得明确施工授权后，普通的内部排查、假设排除、测试辅助分析和连续施工过程不应频繁打断人。

只有以下情况才需要主动汇报：
- 需要人 / Decision AI 做真正决策
- 超出当前任务边界
- 发现高风险操作
- 阻塞且无法自行恢复
- 当前阶段完成
- 最终验证失败或出现重要异常

该规则目前作为候选观察项，不立即施工，先通过 A-177 等真实项目继续收集案例。

### R-009 多 API 管理

**状态：待讨论**

当前实际状态：API 设置页目前只能配置一个 API。

后续需要讨论是否支持多个 API，以及 API、Model、用途/角色之间的管理方式。

当前不施工。

## 四、当前 UI / 产品原则

- 移动端优先。
- 简洁、明确、低负担。
- 人看状态，AI 查日志。
- UI 解决人的理解和操作问题，不把内部复杂性全部暴露给用户。
- 实际手机截图作为 UI 判断依据之一。
- UI 想法先记录，确认后再进入正式施工。

## 五、V0.2.1 UI 要求

**状态：已确认 / 待实现**

V0.2.1 先收敛底部交互结构，不继续增加固定底部功能按钮。

### 1. 底部输入区域

底部区域固定采用：

- 输入框
- 页面切换
- 页面配置
- +
- 语音输入
- 扩展输入

其中：

- 原“模型切换”改为**页面切换**。
- 原“小设置”改为**页面配置**。
- “+”保留入口，具体内容暂不定义。
- 第一版页面切换只包含：**工作区、新对话**。

### 2. 页面切换

当前只需要两个入口：

- **工作区**：管理当前 AI 协作工作区及其配置。
- **新对话**：创建并进入新的 AI 对话，可选择对应 API / Model。

未来增加其他页面时，通过页面切换扩展，不继续向底部增加固定按钮。

### 3. 页面配置

页面配置按钮只配置当前页面，不作为全局设置入口。

工作区页面可配置：

- 当前加入哪些 AI / API
- AI 权限与当前修改权
- GitHub 项目
- 当前分支
- 协作模式
- 其他工作区专属配置

对话页面可配置：

- 当前 API / Model
- 模型参数
- 对话相关设置

### 4. 输入法适配（硬性要求）

**输入框必须始终位于 Android 输入法上方。**

验收要求：

- 输入法弹出后，输入框和底部操作栏整体位于输入法顶部以上。
- 输入框不能被输入法遮挡。
- 多行输入时不能因输入框增长而进入输入法遮挡区域。
- 输入法收起后，输入区域正常回到底部。
- 页面内容区域应随可用高度变化正常调整。
- 必须正确处理 Android IME / Window Insets，不能采用会被输入法覆盖的固定底部布局。

该项为 V0.2.1 UI 验收硬条件。

## 六、状态定义

- **待讨论**：已经记录，但尚未形成明确决定
- **候选**：有价值，等待是否进入施工
- **已确认**：方向已经确定
- **开发中**：正在施工
- **已实现**：代码已完成，尚未完成最终验证
- **已验证**：真实测试确认
- **阻塞**：存在明确阻塞因素
- **废弃**：不再采用
