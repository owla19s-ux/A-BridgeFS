# A-BridgeFS 0.2.1 阶段计划

更新时间：2026-09-30

## 1. 阶段定位

0.2.1 的核心目标不是提前建设完整 Agent 平台，而是证明：

> **真实 Provider + Model 可以驱动 Decision AI / Worker，通过正式 AI↔AI 协议和 Tool Calling，完成一次真实的多轮自动协作施工。**

路线采用：

```
Android Local Runtime
        ↓
真实协作闭环
        ↓
Remote Runtime（后续）
```

Remote 是长期架构方向，不属于当前施工。

---

## 2. 当前正式施工范围

### Phase 1：正式 AI↔AI 协议

目标：

- 明确 Decision AI → Worker 的正式工作请求格式
- 明确 Worker → Decision AI 的结果 / 决策请求格式
- 保留 AI 身份与角色信息
- 不再依赖临时自动交接文本作为正式协议

状态：待施工

### Phase 2：最小 Tool Calling Runtime

第一工具：

```
echo_test
```

目标闭环：

```
Decision AI
    ↓
WORK_REQUEST
    ↓
Worker AI
    ↓
Tool Call
    ↓
echo_test
    ↓
Tool Result
    ↓
Worker AI
    ↓
WORK_RESULT
```

必须使用当前真实 Provider + Model 验证，而不是只验证代码结构。

状态：待施工

### Phase 3：GitHub Read Tool

Tool Calling 成功后再接入 GitHub。

第一批只读能力：

- get_repository
- get_file
- get_workflow_run

目标：

让 Worker 能通过 Tool 读取真实项目状态。

状态：待施工

### Phase 4：GitHub Test Write

使用独立测试仓库，不直接碰正式项目。

第一批写入能力：

- create_branch
- create_commit

状态：待施工

### Phase 5：Commit → Actions → Verify

建立真实施工闭环：

```
Worker
 ↓
Commit
 ↓
GitHub Actions
 ↓
Workflow / Check Run / Job
 ↓
Verify
 ↓
真实结果
 ↓
Worker 继续 / 回报
```

第一版采用轮询，不做 Webhook。

状态：待施工

---

## 3. 后续阶段

以下属于 0.2.1 的后续目标，但不在当前第一施工批次提前实现：

### Phase 6：Worker 自动继续

普通问题由 Worker 自行处理；只有真正超出授权边界的问题才进入决策请求。

### Phase 7：DECISION_REQUEST

Worker 将真正需要决策的问题交给 Decision AI。

### Phase 8：Task / Execution / Event 持久化

采用最小模型，优先支持：

```
READY
WORKING
WAITING_TOOL
VERIFYING
DECISION_REQUIRED
COMPLETED
BLOCKED
```

不在第一批直接建设完整任务平台。

### Phase 9：Android 重启恢复

在真实执行链已经成立后，再加入状态持久化与 App 重开恢复。

### Phase 10：Remote Runtime

将 Local Worker Runtime 替换 / 扩展为 Remote Worker Runtime。

长期目标：

```
Local Worker Runtime
        ↓
Remote Worker Runtime
```

两者尽量复用：

- Task
- Event
- Tool Call
- Tool Result
- Worker Result

---

## 4. 明确不属于当前施工范围

以下内容本阶段不做：

- Kubernetes
- 多 Worker
- Queue
- WebSocket
- Webhook
- Firebase
- 高可用
- 自动扩缩容
- 24/7 SLA
- 自动 Merge
- 完整 GitHub App
- 复杂 Agent Framework
- 多 Provider 自动切换
- 离线继续 Y 模式
- Remote Server 提前部署

---

## 5. 当前验收原则

每个阶段区分：

- 已设计
- 开发中
- 已实现
- 已验证
- 阻塞

其中：

> **实现不等于验证。**

涉及外部系统时，以真实结果为准。

特别是 GitHub / Actions / Verify：

- 必须按实际 Commit SHA 追踪
- 必须确认对应 Workflow Run / Check Run / Job
- 必须区分 success / failure / cancelled / skipped / in_progress
- 没有真实 Run 时不得推断 Verify 已发生

---

## 6. 第一施工任务

当前不继续扩展架构。

第一任务固定为：

> **检查现有 Decision / Worker / API 实现，并设计并实现 Phase 1 的正式 AI↔AI 协议。**

Phase 1 完成并通过基础验证后，才进入 `echo_test`。

---

## 7. 与当前项目状态的关系

0.2.1 阶段计划建立在当前项目已有能力之上：

- Android 基础工程：已实现
- API / 对话：已实现
- 本地 BridgeFS：已实现
- Decision AI / Worker：已有基础能力
- GitHub 协作：开发中
- 自动 AI↔AI 决策交接：尚未形成正式协议
- Tool Calling Runtime：尚未完成
- Verify 自动反馈：尚未完成
- 状态恢复：尚未完成
- Remote Runtime：后置

本文件是 **0.2.1 当前施工边界**，不替代代码事实，也不把后续阶段视为已实现。
