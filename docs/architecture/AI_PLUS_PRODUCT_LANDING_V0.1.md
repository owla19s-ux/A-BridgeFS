# AI+ 产品落地 V0.1

状态：施工中  
日期：2026-09-28

## 1. 这一次的变化

AI+ 不再要求一次性做成完整的平台。

过去的 AI-V1、Weijia、BridgeFS 等工作，分别验证了 API、身份、权限、执行、记录等不同部分。

现在改为：

**保留成熟设计思想，重新适配到一个能运行的 Android 落地点。**

当前落地点：

**A-BridgeFS**

名字变化、项目边界变化，不代表之前的设计作废。

## 2. 第一性闭环

用户
→ 项目
→ 对话
→ AI
→ 本地操作请求
→ Permission / Policy
→ BridgeFS
→ Android
→ Receipt
→ 对话继续

API 对话和本地执行必须属于同一条链。

## 3. 项目不是普通文件夹

第一版的 Project 是一个“大文件夹式工作空间”：

- 对话记录
- 执行记录
- 项目名称
- 后续可挂接项目文件
- 后续可挂接版本、决策、变化记录

目标不是做传统项目管理软件，而是让 AI 与用户围绕一个事情产生的工作过程能够长期留下来。

## 4. 历史记录的处理原则

旧设计和讨论可以整理，但不强制全部迁移进 App。

迁移优先级：

1. 已验证的工程能力
2. 已确认的架构原则
3. 对当前产品直接有帮助的历史记录
4. 尚未确认的探索性想法

未确认的历史想法不能自动变成产品事实。

## 5. UI 原则

可以参考此前 BridgeFS 的：

- 悬浮球
- 面板
- 状态切换
- 操作按钮
- 执行结果展示

但 A-BridgeFS 不复制旧 UI 的技术限制。

当前 UI 优先保证：

- 对话清楚
- 项目清楚
- 权限清楚
- 执行结果清楚
- API 设置可用

后续再逐步恢复更完整的视觉设计。

## 6. 权限原则

长期授权和单次确认分开。

授权范围内且策略允许：

**自动执行。**

高风险或明确设置为需要确认：

**进入确认。**

超出授权范围：

**拒绝。**

Permission / Policy 必须存在于执行边界，不能只存在于 Prompt 或 UI。

## 7. 第一版之后

暂不实现：

- 多 AI 自动协作
- 书记员
- Scheduler
- 完整长期记忆
- NeuroMesh
- Browser Manager
- 云同步
- 多设备同步
- 完整 Project Engine

但数据模型和接口不应阻塞这些方向。

## 8. 当前产品判断

A-BridgeFS 是 AI+ 的当前第一个实际产品落点，而不是 AI+ 的全部。

它首先证明一件事情：

**AI 能否在用户明确授权的本地环境中持续工作，并把工作过程真实记录下来。**

如果这个闭环成立，后续能力再逐层增加。
